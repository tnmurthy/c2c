The work below closes that gap systematically.

## Autonomous Loop & Verification Commands

### Verification Commands
- **Frontend Next.js Build:** `npm run build`
- **Frontend Lint:** `npm run lint`
- **Playwright E2E Tests:** `npm run test:e2e`
- **Backend API Server Health:** `python -m uvicorn api.main:app --port 8000` (check `/health`)
- **Backend Pytest:** `pytest tests/`

### Loop Execution Protocol (Self-Correction Cycle)
When executing tasks in autonomous loop mode:
1. **Pick Task:** Pick the topmost uncompleted task in the active Phase below.
2. **Implement:** Write clean, minimal diffs meeting the specific Acceptance criteria.
3. **Run Verification:** Run the relevant verification command (`npm run build` or `pytest tests/`).
4. **Self-Healing Loop:** If verification fails:
   - Read the exact error output / stack trace.
   - Refactor implementation to fix the root cause.
   - Retry verification (max 5 attempts).
5. **State Update & Commit:** Check off the task, commit (`feat:`/`fix:`), and move to next task.

## Phase 1 — Foundation Fixes (do first, blocks everything else)

### P1-A: Fix Python packaging — remove sys.path hacks

**Problem:** `api/main.py` uses `sys.path.append` to reach service modules at runtime.
This breaks in Vercel serverless (path context differs) and causes silent import failures.

**Tasks:**
1. Add `__init__.py` to: `services/job-intel-desk/`, `services/market-scout/`,
   `services/agent-recruiters/`, `scripts/`
2. In `api/main.py`, remove the three `sys.path.append(...)` lines
3. Update all cross-service imports to use proper relative/absolute package paths
4. Verify: `python -m uvicorn api.main:app --reload` starts cleanly from repo root
   with no import warnings

**Acceptance:** `uvicorn api.main:app` starts, `/health` returns `{"status":"ok","db":"connected"}`

---

### P1-B: Fix silent AI bypass in assessment_router.py

**Problem:** If `C2C_Orchestrator_V2` fails to import, a fake class is silently substituted
that always returns `{"final_status": "CERTIFIED"}`. Students get fake results in production
with no error surfaced anywhere.

**File:** `api/routers/assessment_router.py` lines ~19-30

**Tasks:**
1. Replace the `except ImportError` silent fallback with:
   ```python
   except ImportError as e:
       C2C_Orchestrator_V2 = None
       logger.critical(f"❌ CRITICAL: C2C_Orchestrator_V2 failed to import: {e}. "
                       "Agent evaluation will be DISABLED until this is resolved.")
   ```
2. In `run_agent_recruiters()`, guard before using the orchestrator:
   ```python
   if C2C_Orchestrator_V2 is None:
       logger.error(f"[WORKER] Skipping agent-recruiters for {student_id} — orchestrator unavailable")
       return
   ```
3. Add a `/api/health/agents` endpoint that returns `{"orchestrator": "ok"}` or
   `{"orchestrator": "unavailable", "error": "import failed"}` so ops can monitor this

**Acceptance:** Intentionally break the import path → health endpoint returns `unavailable`,
no fake CERTIFIED results appear in DB.

## Phase 2 — Wire the Core E2E Journey (the demo that sells colleges)

**Goal:** Student completes assessment → DevelopmentReport generated by AI → dashboard shows it.
This is the minimum viable demo needed to close the first college.

### P2-A: Supabase trigger → agent-recruiters webhook

**Tasks:**
1. In `supabase/` create a migration: `add_assessment_webhook_trigger.sql`
   - Add a Supabase Database Webhook (or Edge Function) on `assessment_results` table
     `INSERT` event that POSTs `{student_id, result_id}` to `/api/agents/run-ordeal`
2. In `api/routers/` create `agents_router.py`:
   ```python
   POST /api/agents/run-ordeal
   # Body: {student_id: str, result_id: str}
   # Verifies webhook secret header (SUPABASE_WEBHOOK_SECRET env var)
   # Calls run_agent_recruiters(student_id) as BackgroundTask
   # Returns 202 Accepted immediately
   ```
3. Register `agents_router` in `api/main.py`
4. `run_agent_recruiters` (already exists in assessment_router) should write its output
   to a `development_reports` table (create migration if not exists):
   ```sql
   create table if not exists development_reports (
     id uuid primary key default gen_random_uuid(),
     student_id uuid references students(id),
     result_id uuid references assessment_results(id),
     profile_summary text,
     actionable_feedback jsonb,
     ordeal_status text,
     created_at timestamptz default now()
   );
   ```

**Acceptance:** Trigger assessment submit via API → check `development_reports` table →
row appears within 10 seconds with non-null `profile_summary`.

## Phase 3 — Revenue Pipeline (CRM + Employer Matching)

### P3-A: Build CRM router (college sales pipeline)

**File:** `api/routers/crm_router.py` — currently 37 bytes (empty)

**Tasks — build a minimal but functional B2B CRM:**

```
POST /api/crm/leads          — create a college prospect lead
GET  /api/crm/leads          — list all leads (admin only)
PATCH /api/crm/leads/{id}    — update stage (PROSPECT→DEMO→PROPOSAL→CONTRACT→LIVE)
POST /api/crm/leads/{id}/notes — add a follow-up note
GET  /api/crm/leads/{id}/notes — list notes for a lead
```

**Supabase table (create migration):**
```sql
create table crm_leads (
  id uuid primary key default gen_random_uuid(),
  institution_name text not null,
  contact_name text,
  contact_email text,
  contact_phone text,
  stage text default 'PROSPECT',  -- PROSPECT|DEMO|PROPOSAL|CONTRACT|LIVE
  student_count int,
  contract_value_inr int,
  owner_email text,               -- your email for assignment
  notes jsonb default '[]',
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
-- RLS: admin only (add in Phase 5)
```

All endpoints require `require_role(["admin"])`.

**Acceptance:** Can POST a lead, PATCH its stage to CONTRACT, GET all leads — data persists in Supabase.

### P3-B: Wire employer job posting → candidate scoring → leads table

**File:** `api/routers/employer_router.py`

**Tasks:**
1. On `POST /api/employer/jobs` (job creation), after saving the job, fire a BackgroundTask:
   `score_candidates_for_job(job_id, job_data)`

   - Fetch all students with completed assessment results
   - For each student, compute a `fit_score` (0-100) against the job's required dimensions

3. Add `GET /api/employer/jobs/{job_id}/candidates` that returns scored leads for that job

**Acceptance:** Create a job via API → after 10s, `leads` table has rows with fit_scores → 
employer endpoint returns ranked candidates.

## Phase 4 — Modularise Core IP

### P4-A: Extract scoring engine from assessment_router.py

**Problem:** Scoring thresholds and archetype logic are hardcoded strings inside a 727-line router.
This is the core IP and must be testable and configurable independently.

**Tasks:**
1. Create `services/scoring_engine/engine.py`:
   ```python
   # Config-driven thresholds loaded from scoring_config.json
   def compute_archetype(scores: dict) -> str: ...
   def generate_development_report(scores: dict, archetype: str) -> dict: ...
   def compute_fit_score(student_scores: dict, role_type: str) -> float: ...
   ```
2. Create `services/scoring_engine/scoring_config.json`:
   ```json
   {
     "archetype_rules": { ... },
     "feedback_thresholds": {
       "AQ": {"low": 50, "high": 80},
       "SQ": {"low": 40, "high": 80},
       "IQ": {"low": 50, "high": 80},
       "EQ": {"low": 40, "high": 80},
       "SpQ": {"low": 40, "high": 75}
     },
     "role_weights": { ... }   // from 5Q table in README
   }
   ```
3. In `assessment_router.py`, replace the hardcoded `generate_development_report` function
   with an import from `services.scoring_engine.engine`
4. Write `tests/test_scoring_engine.py` with at least 5 unit tests covering archetype assignment

**Acceptance:** `pytest tests/test_scoring_engine.py` passes. Changing a threshold in
`scoring_config.json` changes the output without touching router code.
